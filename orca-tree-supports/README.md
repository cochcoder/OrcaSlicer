# orca-tree-supports

A Rust reimplementation of OrcaSlicer's tree/organic support generation subsystem.

## Overview

This crate provides the core algorithms for generating tree-style support structures
for FDM 3D printing. It is designed as a drop-in replacement for the C++
`TreeSupport` implementation in OrcaSlicer, with the following advantages:

- **Memory safety**: Rust's ownership system eliminates crashes from use-after-free,
  double-free, and data races.
- **Parallelism**: Heavy use of Rayon for parallel overhang detection, branch
  generation, and collision checking.
- **Clean architecture**: Modular design with clear separation of concerns.
- **FFI compatibility**: Stable C API via `extern "C"` functions and `#[repr(C)]` types.

## Modules

| Module               | Description                                             |
|----------------------|---------------------------------------------------------|
| `config`             | Configuration parameters (mirrors C++ TreeSupportSettings) |
| `mesh`               | Indexed triangle mesh with AABB acceleration            |
| `overhang_detection` | Per-layer overhang area detection (parallelized)        |
| `branch_generation`  | Tree branch placement, node dropping, radius progression |
| `collision`          | Collision/avoidance volume computation (cached, thread-safe) |
| `interface_layers`   | Support roof/floor generation                           |
| `placement`          | Final geometry output (per-layer polygons)              |
| `ffi`                | C-compatible FFI boundary                               |
| `utils`              | Error types, coordinate helpers, profiling              |

## Building

### Prerequisites

- Rust 1.70+ (2021 edition)
- C/C++ toolchain (for FFI linking)

### Build the library

```bash
cd orca-tree-supports
cargo build --release
```

This produces:
- `target/release/liborca_tree_supports.a` (static library)
- `target/release/liborca_tree_supports.so` (shared library on Linux)
- `target/release/liborca_tree_supports.dylib` (shared library on macOS)
- `include/orca_tree_supports.h` (C header, generated by cbindgen)

### Run tests

```bash
cargo test
```

### Generate documentation

```bash
cargo doc --open
```

## Integration with OrcaSlicer C++

### 1. Link the Rust library

Add to your CMakeLists.txt:

```cmake
# Build the Rust crate
add_custom_command(
    OUTPUT ${CMAKE_BINARY_DIR}/liborca_tree_supports.a
    COMMAND cargo build --release --manifest-path ${CMAKE_SOURCE_DIR}/orca-tree-supports/Cargo.toml
    WORKING_DIRECTORY ${CMAKE_SOURCE_DIR}/orca-tree-supports
)

# Link against the static library
target_link_libraries(libslic3r PRIVATE
    ${CMAKE_BINARY_DIR}/liborca_tree_supports.a
)
target_include_directories(libslic3r PRIVATE
    ${CMAKE_SOURCE_DIR}/orca-tree-supports/include
)
```

### 2. Call from C++

```cpp

        for (uint32_t i = 0; i < output->layer_count; i++) {
            const auto& layer = output->layers[i];
            // Convert layer polygons to ExPolygons...
        }
    }

    orca_tree_support_destroy_output(output);
    orca_tree_support_destroy_handle(handle);
}
```

## Algorithm Overview

The tree support generation follows this pipeline:

1. **Overhang Detection**: Identify mesh triangles that overhang beyond the
   configured angle threshold. Parallelized per-layer with Rayon.

2. **Contact Point Generation**: Place initial support nodes at overhang
   positions, respecting branch distance and tip density parameters.

3. **Node Dropping**: Grow branches downward from contact points toward the
   build plate. At each layer, nodes move laterally to avoid model collisions
   and merge with nearby branches.

4. **Radius Progression**: Branch radius increases from the tip diameter at
   the top to the full branch diameter toward the base, following the
   configured diameter angle.

5. **Interface Layers**: Generate roof (top) and floor (bottom) interface
   layers with denser fill patterns for better surface quality.

6. **Output Generation**: Convert the branch tree into per-layer polygons
   suitable for toolpath generation.

## Performance Notes

- **Parallel overhang detection**: Each layer is processed independently via Rayon.
- **Parallel branch dropping**: Independent branches are dropped in parallel.
- **Cached collision queries**: Collision data is computed lazily and cached
  per (radius, layer) pair with thread-safe `RwLock`.
- **Profile with**: `cargo flamegraph` (requires `cargo install flamegraph`).
